# Codex follow-on: checked closed-fragment reuse, with a non-graph baseline

Run this only after the typed boundary integration and its actual Lean regressions pass. This is a separate task and experiment, not permission to expand the preceding implementation indefinitely.

## Objective

Test whether boundary-aware retrieval of completed local proof fragments reduces repeated tactic work beyond the existing whole-state/group searches and an ordinary typed proof-term cache. You must not claim that basic goal caching or metavariable coupling is new: the baseline already implements them.

## Reuse contract

1. From an actual solved local obligation, obtain its assigned proof expression in the appropriate saved context. Verify it is closed relative to a dependency-closed local telescope, with no unresolved term or universe metavariables and no unapproved axioms.
2. Compute local support from the proof AND target, recursively through local types and retained definition values. Export a portable abstraction. Keep declaration and source-prefix provenance.
3. At a new goal, propose a typed context substitution. This may rename and instantiate parameters and tolerate irrelevant additional assumptions; it may not silently change a type or use a later theorem.
4. In a cloned current Lean state, elaborate/apply the transported term at the new target. Accept reuse only on actual Lean success, record all assignments, and retain final complete-proof replay.
5. Failed retrieval or transport consumes a measured budget and returns to ordinary search. Do not delete baseline alternatives. Failed attempts cannot modify the committed graph.

Begin with same-environment, completed fragments. Arbitrary open fragments with shared witness assignments are out of scope. A match score or canonical hash is never a proof certificate.

## Baselines

Keep the existing faithful whole-state and coupled-group engines, applying the same confirmed correctness repairs to each. Add:

- a conventional typed proof-term cache;
- a boundary/graph-indexed cache with the identical fragment pool and transport checker.

Hold proposer, available declarations, candidate counts, trust rules, and budgets fixed. Do not compare against an intentionally weak cache. Separate a retrieval-quality gain from a graph-representation gain.

## Pilot and registration

First run only a declared correctness pilot. Use conjunction transport, equality congruence, context weakening, and incompatible witness tests. Create a separate held-out mathematical fragment inventory without inspecting which arm wins. Before the measured run, commit a draft-derived preregistration containing exact corpus IDs, train/test separation, seeds, model settings, exclusions, hypotheses, multiple-testing handling, resource budget, cost-accounting policy, and stop criteria.

Do not call a retrospectively written plan a preregistration. Freeze all previous experiments.

## Cost accounting

Report model requests and generated tokens, Lean candidate calls, boundary exports, match proposals, transport checks, failed matches, and final replay costs. Common cached draws are useful for paired candidate comparison but cannot be credited as runtime savings to whichever arm runs later. Run isolated cold-cache timing trials separately with randomized order and fixed warmup.

Count theorems as the paired units; seeds are repeated measurements, not independent theorems. Report confidence intervals and setup failures, not only pooled successes. Nonsignificance is not equivalence. A non-inferiority claim needs a preregistered margin.

## Required outputs

Provide an actual Lean transport module, cache implementations, a fixture runner, replayable fragment records, a fresh protocol, raw experiment rows, and a summary regenerated by `--check-committed`. Include every rejection reason and cost. If model execution is unavailable, deliver and validate the correctness pilot but mark the measured search study unrun.

## Decision rule

If useful reuse is rare, report limited applicability. If replay overhead outweighs saved work, report a cost failure. If the ordinary cache matches the graph cache, retain the useful typed cache and state that graph-specific value was not demonstrated. A negative result is acceptable; fabricated or unmeasured improvement is not.
